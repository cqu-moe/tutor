# Scoped learner memory and effect identity

The old pi-memory extension exposed the entire tagged Markdown file in both injected context and tool reads. A CLI regression demonstrated that another course's progress was returned; prompt-only exclusion did not enforce the memory contract.

Tutor now uses a Session-scoped document in official pi-durable SQLite storage for learner facts, scoped recovery records, pending legacy inputs and memory-effect receipts. This is domain storage, with no parallel task, submission or workflow implementation. Official per-course Harness conversations continue to own execution; maintenance uses a separate conversation from the route in the same Harness. The old pi-memory runtime dependency is removed.

The course UUID established by `ensureCourse` owns facts. Global is explicit; the tool boundary validates selection and global-write intent. Initial import/generation has no mutation capability. Feedback is atomically persisted in the admitted official `tutor.request` entry, then resolved from the tool's original assistant ancestry on recovery. It is not a mutable current-request flag that could authorize an earlier unfinished invocation.

Official `api.callId` is a provider call ID and may repeat. `api.taskId` is the stable persisted invocation identity. A memory effect and its returned domain result commit in the same document transaction, so safe replay can return an already-applied result after death before the official tool-result receipt. A regression blocks that receipt with a real SQLite writer after tool intent, observes the effect via CLI, kills the process and reopens the original admitted request. No test-only production pause or alternate workflow engine is needed. Memory tools use official sequential round scheduling, since a reproduced two-write response otherwise let separate document kernels overwrite one another. Durable memory tools are model-callable; nested concurrent callers must use the application API under their own ownership boundary.

Chapters in `course.json` remain the only learning-progress authority. Memory reads project their status. Progress effects record a narrow intent before calling the existing course setter and complete it afterwards; replay compares status first. Legacy progress only maps when chapter/status are unambiguous and do not override newer marks. Import prepares migration before adding provisional chapters; route proposal does not consume pending progress for provisional targets. A failed import can therefore retry without losing an old fact behind a completed migration receipt. This closes the course-file/document interruption gap without duplicating progress text.

Legacy Markdown, daily records, recovery JSON and session originals remain unchanged. Imported IDs prevent resurrection of deleted facts. Pending unknown/mixed input is retained but excluded from model context; migration is retryable. Old unscoped revision history is retained but never loaded. Full task admission/recovery, concurrency ownership and a data-directory lock remain ticket #18.
