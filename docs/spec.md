# Tutor：组合现成工具的个人课程讲解 Agent

状态：已根据需求讨论形成规格；用户已确认测试边界。项目尚未配置 issue tracker，本文尚未发布；发布时使用 `ready-for-agent` 标签。

## Problem Statement

学习者希望把课程 PDF 和截图变成能够独立阅读、替代课件的讲解稿。现有通用 Agent 的输出可能只整理知识点，缺少必要的前置知识、原因解释、关键推导和帮助理解的例子。学习者因此仍需反复补充要求，并在课件、对话和生成文件之间查找信息。

学习过程也会跨越多次对话。Agent 需要记住某门课学到哪里、学习者偏好的讲解方式和具体薄弱点，并据此调整后续教学。会话历史和已生成文件本身不能可靠代表学习者的理解情况。

课程材料经常包含公式、表格、电路图和示意图。讲解稿既要完整覆盖所选内容，也要保留图表的正确关系并提供可读的 PDF。用户希望组合已有 Agent、记忆、OCR、绘图和排版工具，维护一个适合自己使用的本地工具。

## Solution

提供个人本地 CLI。学习者选择课程、课程资料和讲解范围，Agent 读取资料及相关学习者记忆，提出教学路线；学习者调整并确认后，Agent 生成完整讲解稿，支持随后重讲某节、补推导或更换例题。

讲解稿覆盖指定范围内的全部不同知识点、公式条件和方法，允许按学习依赖重排、补充前置知识、合并重复讲述并精选代表例题。交付 Markdown、Typst、PDF 和必要图片；第一版重点做好 PDF 中的静态图表。

Agent 自动记录明确的学习进度、学习偏好和困难。行为推测保留依据并标为待验证，学习者可随时查看、纠正和删除。模型接入和云 OCR 均由用户配置，学习者记忆保存在本机。

## User Stories

1. 作为学习者，我希望从本机 CLI 启动课程讲解任务，以便沿用自己熟悉的工作方式。
2. 作为学习者，我希望指定本次任务所属课程，以便 Agent 使用对应的课程资料和学习者记忆。
3. 作为学习者，我希望提供课程 PDF，以便直接使用已有课件、教材章节或题解。
4. 作为学习者，我希望补充截图，以便让 Agent 读取 PDF 之外的题目、公式或图表。
5. 作为学习者，我希望指定页码或章节范围，以便控制本次讲解的内容。
6. 作为学习者，我希望 Agent 读取资料后先提出教学路线，以便在完整生成前判断学习内容与顺序。
7. 作为学习者，我希望调整教学路线并确认后再生成讲解稿，以便按自己的目标学习。
8. 作为学习者，我希望讲解稿完整覆盖所选范围的不同知识点、公式条件和方法，以便将其作为日常学习材料。
9. 作为学习者，我希望 Agent 补充必要的前置知识，以便在基础不足时仍能理解当前内容。
10. 作为学习者，我希望讲解说明概念和方法为什么成立、何时适用，以便理解而不只是记住结论。
11. 作为学习者，我希望关键推导展开必要步骤，以便能够跟随并复现推理。
12. 作为学习者，我希望讲解按学习依赖重组并合并重复内容，以便形成连贯的理解。
13. 作为学习者，我希望例题具有代表性且解释解题过程，以便学会应用方法而不必重复所有原题。
14. 作为学习者，我希望原有公式、题目和图片可以回查课程资料，以便核对疑问和识别新增内容。
15. 作为学习者，我希望新增例题明确标注，以便区分课程资料与 Agent 的补充。
16. 作为学习者，我希望 Agent 标出资料中的识别疑点，以便在错误影响后续讲解前处理它们。
17. 作为学习者，我希望要求重讲某一节，以便针对没理解的部分获得新的解释。
18. 作为学习者，我希望要求补充推导或更换例子，以便继续完善已有讲解稿。
19. 作为学习者，我希望修订时复用已有解析结果，以便减少重复处理课程资料。
20. 作为学习者，我希望获得清楚的静态表格，以便阅读真值表、对照关系和计算结果。
21. 作为学习者，我希望电路图和示意图的符号、标注与连接准确，以便根据图理解结构和关系。
22. 作为学习者，我希望 Agent 预览并修正图表，以便避免将重叠、缺字或错误连接带入讲解稿。
23. 作为学习者，我希望 PDF 中的必要图表支持矢量输出，以便放大或打印时仍可阅读。
24. 作为学习者，我希望同时保留 Markdown、Typst、PDF 和所需图片，以便阅读、修改和重新编译讲解稿。
25. 作为学习者，我希望原始课程资料保持可用，以便随时回查并重新处理。
26. 作为学习者，我希望 Agent 记住某门课明确反馈过的学习进度，以便下次继续学习。
27. 作为学习者，我希望 Agent 记住讲解深度、表达和例题安排等学习偏好，以便减少重复说明。
28. 作为学习者，我希望 Agent 记住具体薄弱点，以便后续教学路线和解释有针对性。
29. 作为学习者，我希望不同课程的进度和薄弱点分别保存，以便避免课程之间混淆。
30. 作为学习者，我希望适用的通用学习偏好能跨课程使用，以便保持一致的学习体验。
31. 作为学习者，我希望当前明确提出的要求优先于过去的学习偏好，以便临时调整讲解方式。
32. 作为学习者，我希望 Agent 从对话反馈和可选练习中了解学习情况，以便不被强制测验打断。
33. 作为学习者，我希望明确的进度、偏好和困难自动记录，以便不用逐条确认记忆。
34. 作为学习者，我希望推测出的薄弱点保留依据并标为待验证，以便避免推测变成确定结论。
35. 作为学习者，我希望生成讲解稿不会被当成已经学过或掌握，以便保持学习进度可信。
36. 作为学习者，我希望查看、纠正和删除学习者记忆，以便控制后续讲解依据的信息。
37. 作为学习者，我希望重开会话后仍能取回相关学习者记忆，以便持续学习。
38. 作为学习者，我希望学习者记忆保存在本机，以便无需额外维护托管记忆服务。
39. 作为使用者，我希望复用已有 Magpie 配置并选择模型，以便使用当前可用的模型服务。
40. 作为使用者，我希望提供自己的 API Key 使用 Pi 支持的模型服务，以便按需要选择 provider。
41. 作为使用者，我希望配置兼容接口的地址、协议和模型，以便接入已有网关或本地服务。
42. 作为使用者，我希望独立选择模型服务与 OCR 服务，以便分别满足讲解和资料解析需求。
43. 作为使用者，我希望选择 MinerU 精准解析 VLM 或 Mistral OCR，以便使用适合材料的云解析服务。
44. 作为使用者，我希望服务失败时看到可处理的错误并保留已有工作，以便修正配置或手动更换服务后继续。
45. 作为维护者，我希望优先使用现成工具、SDK 和扩展，以便用少量连接代码完成需求并降低维护成本。

## Implementation Decisions

1. **实现范围**：第一版为单人本地 CLI。自定义实现限于 CLI 入口、课程工作目录、配置读取、工具连接和课程讲解指令；复用现成 Agent 运行时和会话能力。
2. **Agent 运行时**：采用 Pi SDK，复用会话、交互和工具执行能力，加载课程讲解所需的指令与资源。本机已核查版本为 0.82.1，实际集成仍需验证。
3. **任务流程**：选择课程与范围 → 读取课程资料及相关学习者记忆 → 提出教学路线 → 用户调整确认 → 生成讲解稿和图表 → 导出并检查 → 接受局部修订。用户未确认教学路线时，不进入完整讲解稿生成阶段。
4. **课程资料输入**：接收 PDF 和补充截图；PPT 由用户先转 PDF。解析结果保留对应原页与资源信息，保存于课程工作目录以供核对和后续修订。原始资料保留。
5. **云 OCR**：提供 MinerU 精准解析 VLM 与 Mistral OCR 两种配置选择，方案默认 MinerU。优先使用官方 SDK、客户端或 API；两家服务只接入本任务需要的解析与结果保存能力。既有 Poppler 用于原页渲染。
6. **OCR 服务选择与失败**：仅调用用户当前配置的 OCR 服务。服务失败时报告具体问题并保留已有结果；更换服务由用户决定。首版不增加自动跨服务切换。
7. **解析结果核对**：公式、表格和电路关系可回查原页。解析输出中的疑点进入教学路线讨论或修订过程，不能因 OCR 返回成功就视为内容正确。
8. **模型接入**：复用 Pi 内建 provider、认证和模型选择能力，覆盖现有 Magpie、Pi 支持的 BYOK API，以及其支持协议的自定义接口。用户可以配置 provider 和模型，首轮使用现有 Magpie 的 `codex/gpt-6.1-sol` 默认值。
9. **模型能力与凭据**：保留逐模型的 API 协议和文字、图片输入能力配置，按实际调用验证工具执行与读图。认证复用 Pi 的本机凭据或环境变量，课程产物和诊断输出不包含密钥。模型与 OCR 分别配置。
10. **provider 扩展**：特殊协议或登录流程使用 Pi 已有扩展机制及适用的现成扩展。当前接入需求优先通过 Pi 内建支持和配置完成，不建设新的通用模型网关。
11. **讲解内容**：以独立可读、能够替代指定范围课件为目标。完整覆盖不同知识点、公式条件和方法；按理解需要补充前置知识、说明原因、展开关键推导，并精选代表例题。原资料内容保留出处，新增例题标注为新增。
12. **静态图表**：表格复用 Typst 原生能力；电路与数字逻辑图采用 Schemdraw SVG，通用标注示意图优先复用 CeTZ 等现成能力。Agent 查看成图并修正可见问题，同时核对连接与逻辑关系。无需针对这些工具设计新的图表描述语言。
13. **排版与交付**：复用现有课程讲解指令及 Recto/Typst 导出资产，保存 Markdown、Typst、PDF 和必要图片。图表引用完整，Typst 可重新编译，导出后检查 PDF 渲染。
14. **学习者记忆实现**：第一版试用本地 `pi-memory` 扩展，使用其现有存储和读写能力；课程归属、通用学习偏好及记录规则由少量配置与教学指令表达。跨会话的学习者记忆独立于会话恢复和已生成讲解稿的记录。
15. **记忆写入依据**：自动记录明确表达的学习进度、学习偏好和困难，无需逐条确认。学习反馈来自日常对话和可选练习；生成讲解稿不构成学习进度或掌握证据。
16. **记忆范围与推测**：学习进度和薄弱点按课程区分，适用的通用学习偏好可跨课程使用。推测的薄弱点保留依据并标为待验证；当前明确要求优先于历史学习偏好。
17. **记忆维护**：支持查看、纠正和删除，纠正后的记录用于后续讲解。删除和恢复遵循现成扩展的行为，不能把不再参与当前上下文等同于彻底抹除所有历史副本。
18. **故障处理**：缺少依赖、凭据或服务能力时，报告受影响步骤和可处理的原因，保留原始资料与已有成果。不能把未完成的解析、渲染或记忆写入报告为成功。

## Testing Decisions

### 已确认的测试入口

用户已确认以一次完整 CLI 学习任务作为主要测试入口：导入课程资料 → 确认教学路线 → 生成和修改讲解稿 → 重开会话取回学习者记忆。

测试观察使用者能看到的对话阶段、产物、错误和跨会话行为，不依赖内部函数、对象布局、逐工具调用次数或模型生成文字的逐字一致性。CLI 输入和最终可见结果是主要断言边界；为了重复验证，外部模型与 OCR 的响应可在现有 SDK 或网络边界固定。固定响应测试不能替代真实服务与教学质量验收。

### 自动化行为检查

| 验证范围 | 从 CLI 观察的预期行为 |
| --- | --- |
| 课程与资料输入 | 读取指定课程、PDF/截图和范围，产物能对应原页；无效输入给出可处理的错误 |
| 教学路线确认 | 先出现教学路线；调整反映在后续任务中；确认前不生成完整讲解稿 |
| 讲解稿生成与修订 | 确认后生成约定产物；重讲、补推导或换例题体现在修订结果中，已有解析可被复用 |
| 模型和 OCR 配置 | 请求使用选定的 provider、模型及 OCR 服务；两类配置独立；错误配置不会被当成成功 |
| 导出产物 | Markdown、Typst、PDF 与必要图片存在且引用完整；使用真实排版工具可重新编译，不能仅断言文件名存在 |
| 明确学习反馈 | 保存明确进度、偏好和困难；重开进程后可查看并在后续教学路线中使用 |
| 推测与学习进度 | 推测薄弱点带依据和待验证状态；只生成讲解稿不会推进学习进度或宣称掌握 |
| 课程范围 | 两个测试课程的进度和薄弱点互不混淆；通用偏好按规则使用，当前要求可覆盖历史偏好 |
| 记忆维护 | 查看、纠正和删除影响后续读取；删除行为符合扩展约定，不声称清除了全部历史副本 |
| 失败保全 | 模型、OCR 或导出失败时能看到具体失败，原始资料和已有成果仍可用；诊断不泄露凭据 |

自动化测试在独立测试课程和测试记忆目录中运行，模拟进度和薄弱点不进入用户的真实学习者记忆。覆盖配置变化、确认前后和失败后的可见行为，避免为每个连接工具分别搭建一套内部测试接口。

### 真实服务与材料验收

首次使用现有数字化设计第二章“布尔代数与逻辑门”课件，拟取 PDF 第 21–24 页的 Boolean Functions / Complement of a Function 小节。该范围包含公式、真值表、逻辑门实现和例题；生成时补充必要前置知识。

1. 分别配置 MinerU VLM 与 Mistral OCR 解析同一小段材料，核对正文、公式、表格、图像与原页的对应。分别记录真实成功、识别问题或缺少凭据等阻塞。
2. 使用现有 Magpie 模型完成实际对话、工具调用和图片输入验证；在用户有相应凭据时验证 BYOK 切换。仅有 provider 配置或模型清单不算通过实际调用验证。
3. 核对讲解稿对所选范围不同知识点、公式条件和方法的覆盖，检查关键推导和例题；检查电路连接、真值表和公式是否一致。
4. 重新编译 Typst，并逐页查看 PDF，检查文字、公式、表格、图片引用、标注和连线；确认所需图表可清楚放大。
5. 在隔离测试课程中记录模拟进度、偏好和薄弱点，重新启动后继续任务，检查召回及其对教学路线的影响。
6. 由用户实际阅读并判断是否能通过讲解稿独立理解所选材料。文件生成成功、测试通过或自动评分均不能单独证明“足以替代课件”。

### 测试先例与证据界限

项目目前只有需求文档，没有源代码、既有测试框架或可直接复用的项目测试。此前完成的工具探测、文档核查、局部 PDF 文本读取和单页渲染/OCR 检查只是环境证据；未完成 Pi、云 OCR、图表导出和跨会话记忆的组合验证。

实现时优先使用所选运行时已有的测试工具和最高层调用入口。实际验收报告分别记录自动化行为检查、真实外部服务结果与人工教学质量反馈；未运行的检查明确标为未验证。

## Out of Scope

- 多用户账号、在线平台、多设备同步及托管学习者记忆服务。
- 网页入口、OpenUI 交互展示、交互电路模拟和动态图表。
- 自研 Agent 运行时、记忆引擎、通用模型网关、图表语言或 OCR 任务管理服务。
- 为 OCR 新建通用 MCP 适配层，或在当前两家服务之外扩展 OCR 插件体系。
- 直接处理 PPT 源文件；首版使用用户导出的 PDF。
- 将本地 OCR 作为首选方案，或无提示地自动切换云服务。
- 强制测验、自动认定已掌握、自动给用户附上整体能力标签。
- 复制所有原始例题，或无边界地扩展到指定课程资料之外的完整教材。
- 穷尽验证 Pi 支持的所有 provider 和模型，或保证弱模型达到特定模型的教学质量。
- 将删除记忆解释为物理清除所有历史副本。

## Further Notes

- 本文综合已讨论的产品方向与第一版工具组合，不继续开展需求访谈。模型接入按用户最新澄清保留 Magpie、BYOK 和自定义兼容接口，具体默认模型不构成产品限制。
- 原 ChatGPT 对话的读取结果只包含部分用户消息，助手回复正文未取得；本文不声称复现其不可见方案。
- 可复用工具已做文档或配置核查，但 `pi-memory`、Schemdraw、CeTZ、两家云 OCR 与本项目的完整集成尚未验证。已有安装不等于该组合已可用。
- 真实 OCR 验收需要相应服务的凭据；当前未向 OCR 服务上传课件。首次试用应记录识别疑点和实际服务限制，不将“接口已封装”当作验收完成。
